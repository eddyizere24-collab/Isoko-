# Photos package report — 2026-11-16

## Scope
Package A: immediate persistence of seller avatar/logo/cover, separate logo object prefix, broken-image fallbacks, and a server-enforced daily upload-attempt quota.

## Changes in this branch
- `SellerShopSettingsPage.tsx`: uploads save the matching profile or shop record immediately after Object Storage succeeds; success/error feedback is shown in Kinyarwanda; avatar, logo and cover have separate areas and touch targets.
- `ShopPage.tsx`: seller avatar and shop logo no longer overlap the cover; public shop images use a fallback component.
- `SafeImage.tsx`: reusable broken-image fallback and development-only diagnostics.
- `api.ts`: added the distinct `logo` upload kind.
- `isokoapi/index.mjs`: added the `logos/<seller-id>/` prefix, role/ownership checks and server-side quota RPC invocation.
- `019_seller_upload_daily_quota.sql`: corrected the quota table seller key to `text` and uses Neon Auth's `auth.user_id()` because Production `profiles.id` and `profiles.auth_user_id` are text, not UUID. The RPC limits each seller to 30 accepted upload attempts per UTC day.
- `docs/ops/PRODUCTION_STEPS.md`: added read-only Production evidence and exact owner-gated steps for migration 019 and Function deployment.
- `docs/RULES.md`: records the operational and upload rules.
