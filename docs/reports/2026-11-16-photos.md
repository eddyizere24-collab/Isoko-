# Photos package report — 2026-11-16

## Scope
Package A: immediate persistence of seller avatar/logo/cover, separate logo object prefix, broken-image fallbacks, and a server-enforced daily limit of 30 valid seller image upload attempts.

## Changes in this branch
- SellerShopSettingsPage.tsx: upload saves the matching profile or shop record immediately after storage upload succeeds, shows Kinyarwanda success/error feedback, and gives avatar and logo separate upload areas and touch targets.
- ShopPage.tsx: seller avatar and shop logo no longer use negative top margins over the cover; public shop images use a fallback component.
- SafeImage.tsx: reusable broken-image fallback with development-only warning.
- api.ts: added the logo upload kind.
- isokoapi/index.mjs: added logos/<seller-id>/ storage prefix, validates logo ownership, and checks the seller quota before Object Storage writes.
- 019_seller_upload_daily_quota.sql: creates the text-keyed per-seller UTC counter and derives identity from Neon Auth `auth.user_id()`.
- 020_seller_upload_quota_cap_alignment.sql: aligns existing QA quota function to the intended 30 attempts per seller per UTC day. It is required because QA read-back found an earlier stored cap of 50.
- 021_public_product_identity_status.sql: includes `identity_status` in the nested public product shop object so public product cards can show the Verified seal only after identity verification.
- 022_product_image_owner_prefix.sql: validates both `path_full` and `path_thumb` against `products/<authenticated-seller-profile-id>/` inside seller create/update RPCs. Foreign seller image keys are rejected by the database.
- 023_seller_upload_burst_limit.sql: supplements the 30-attempt daily quota with a per-seller rolling limit of 15 attempts per 60 seconds, keyed by authenticated Neon Auth identity.
- Public verification labels now depend only on `identity_status = 'verified'`; approved listing status is not treated as identity verification.
- The help page no longer falls back to the placeholder WhatsApp number `250788000000`; it shows a contact link only when a valid support number is configured.
- The login screen no longer claims a 30-day session lifetime that has not been proven by the Auth provider.
- docs/RULES.md: documents rules and reasons.
- docs/ops/PRODUCTION_STEPS.md: read-only checks and owner-gated Production apply/deploy procedure.
