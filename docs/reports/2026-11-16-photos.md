## What changed

- Seller avatar is saved to `profiles.avatar_key` immediately after upload, without requiring the seller to press the general Save button.
- Shop logo and cover are saved independently immediately after upload. The new API helper updates only the selected branding field, preserving other unsaved form fields.
- Logo uploads use the distinct `logo` upload kind and the `logos/<seller-id>/...` object prefix. Profile and cover remain in `profiles/` and `shops/`.
- The Neon Function derives the seller identity from the verified request token and calls a server-side daily quota RPC. It never accepts the seller id from the browser.
- Migration 019 adds a private daily counter and a `SECURITY DEFINER` quota function. It enables RLS, revokes direct table access, and grants execution to authenticated users only.
- The quota default is **50 validated upload attempts per seller per UTC day**. This number was not specified in the brief, so 50 is an explicit provisional assumption. A storage write failure after the quota check still consumes an attempt.
- A development-only warning is emitted when a public image URL is rejected by the configured storage origin/path validator.
- The seller avatar is at least 72×72 px and its upload control is at least 44×44 px. The avatar and logo no longer overlap the cover on the public shop page.
- Shop cover, avatar and logo images now use an honest local Imigongo-inspired placeholder on load failure. It is not a fabricated product or seller image.
- Production storage base and CSP were checked and already point to the same Neon storage host and correct public bucket path. No Render configuration change was made.

## Open risks / release blockers

- The deployed Production `isokoapi` Function currently has no `logo` upload kind and does not call the new quota RPC. The Function must be updated only after migration 019 is approved and applied to its target branch. Merging the frontend before that Function update would make new logo uploads fail.
- QA migration 019 is installed and the updated Function was deployed successfully as deployment 3 on branch `isoko-full-flow-qa-20261114`. No real authenticated seller upload was performed. The daily quota's identity isolation and limit have not yet been demonstrated end-to-end.
- Upload quotas count validated attempts, not only completed object writes. Review this behaviour and the provisional 50/day limit during QA.
- CI did not publish the required 21 screenshot PNGs; its only artifact was the Neon Function bundle. The existing Playwright smoke test suite does not yet prove the full 320×800/360×800 screenshot matrix.
- The user-facing photo changes are not complete until Playwright and Android screenshots plus a real QA upload prove them.
- Migration 016 is confirmed in Production; no Production migration is needed for its avatar, bio or shop social-link columns.
